# Changelog

All notable changes to **dsh-fonttune** are documented here. Chinese version: [CHANGELOG.md](CHANGELOG.md).

## [0.2.2] - 2026-09-16

### Fixed
- **Simple mode: picking or clearing the CJK slot threw and lost the change** (introduced in 0.2.0). The two handlers behind that slot read `edit[field]`, and no binding of that name exists in the module (the real one is `editing`). The western slot was fine; only the CJK slot broke — in **any** of the three family sections (conversation / interface / code), picking a family in the 中文 slot or clearing that chip threw `ReferenceError: edit is not defined`, wrote nothing and changed nothing on screen. The fix is those two references. **Why it went unnoticed**: the card tests only ever rendered the tree and never invoked a single control callback, so an unwired handler stayed green offline.
- **A guard for that whole class of bug**: `test/render-card.mjs` gained two cases that **fire every rendered control's callback with the payload its control passes** (a slider's min/max, every option of a segmented control, the family picker's `onPick`/`onRemove`, the preset select's full preset entry, a text input's DOM event, every `<button>`'s `onClick`) and assert that none throws — plus a separate assertion that the three CJK slots really *wrote* into the settings, not merely failed to throw. Negative control: injecting the 0.2.1 code turns both cases red; restoring the fix turns them green.
- **`lib/` can no longer drift from `src/` silently**: the new `test/artifacts.mjs` re-renders the build in memory and compares it byte for byte with the committed `lib/client.js`, `lib/shared.cjs` and `lib/index.js` (run by `npm run verify` and by `prepublishOnly`). Every other suite reads `lib/`, so a source-only edit used to be tested — and shipped — as the previous build. `build.mjs` was split into pure functions (`renderArtifacts` / `readSources`) and no longer has side effects when imported.
- **The release workflow never ran the tests**: `npm pack` does **not** trigger `prepublishOnly` (only `npm publish` does), so the tag-triggered release had always packed an untested artifact. It now installs and runs `npm run verify` before packing — deliberately **without** building first, because `test/artifacts.mjs` is exactly the check that the committed `lib/` is what the current `src/` produces, and a build step would mask that — and asserts that the tag equals the `package.json` version.
- **The CHANGELOG extraction matched version prefixes**: the release body used `index(line, "## " pat)`, so `0.2.1` also matched a `0.2.10` heading. It now matches `## <version> ` exactly and **fails the job** when the version has no section (it used to fall back to generated notes silently).
- **Two common CJK family names were not recognised**: `MS PGothic` and `MS PMincho` were treated as non-CJK (while `MS Gothic` and `MS Mincho` were fine), which feeds the simple mode's CJK slot. Fixed to `ms ?p?(?:gothic|mincho)`, the safe direction for a name heuristic.
- **`shiftTokens` guards zero**: a zero offset used to emit a real `calc((14px) + 0px)` declaration that disagrees with `isDormant` and `sameValueSet`. Unreachable today (the call sites guard), but a trap for the next caller.
- **`build.mjs --watch` watched files instead of the directory**: after an editor renamed a source, the process kept waiting on a dead inode and never rebuilt. It now watches `src/` and filters by name, and logs each successful rebuild.

### Changed
- **Documentation corrections**: the README's "editing `src/client.js` is enough after a refresh" omitted the essential step — the browser loads `lib/`, so `node build.mjs` comes first (both languages). The claim that "the DSH market runs a host-compatibility preflight against `engines.dsh` / `dshReleases` / `peerDependencies`" has no implementation anywhere in the local rc.2 distribution, so it now says what is true: the market entry **states** those requirements so the host a version needs can be checked before installing.
- `package.json`: added the test-only `devDependencies` entry (`@deepseek-ai/schemastery`) and a `verify` script; the compatibility table gained 0.2.2.

## [0.2.1] - 2026-09-16

### Fixed
- **"Turning following off leaves the interface weight at the followed value, and reset does nothing"** (reproduced on a real machine): the stylesheet reaches the page **twice** — the host half renders one copy into the served index for the first frame (`webserver/index-inject`) and the browser half keeps a second one — and the served copy is only rebuilt on the **next index render**. With both present, adding or changing a rule is fine (the browser half's copy comes later and wins at equal specificity), but **removing a rule cannot work**: turn following off, or reset the interface weight, and the browser half's fresh stylesheet no longer contains that `font-weight` rule while the served copy still does — so the interface stayed at the followed 480 until the page was reloaded. Two changes: ① the host half now emits an **`html` row** (`<style data-plugin="dsh-fonttune" data-plugin-css="dsh-fonttune">…</style>` instead of an un-stamped `style` row) and the browser half **adopts that element** instead of appending its own (`createStylesheet` looks it up first, falls back to creating one, and re-creates if it ever leaves the document) — one element for the element's whole life, so rules can be added *and* removed. Verified live: the new "turn following off without reloading" step in `test/weight-verify.mjs` shows the interface going 480 → 400 (DSH's own) immediately, the stylesheet count staying at `count=1`, and the served index really carrying the stamped `<style>`.
- **Switching from following to not-following no longer bounces the interface back to its own old value**: turning the switch off used to just flip the flag, so the interface fell straight back to whatever it had stored (usually nothing → DSH's default) while the slider still read 400 and disagreed with the page. Now **the values the interface was showing are written into its own two fields as the switch goes off** (the family from the conversation, the weight from the conversation — the effective values `resolveAxes` expanded), so switching off changes nothing visually and the sliders continue from there; an axis the conversation does not set (empty family, unset weight) clears the interface's own field instead, keeping DSH's default. The expected walkthrough is therefore: following at 480 → switch off → the interface is still 480 and the slider reads 480 → adjust it, or reset for 400.
- **The interface weight is back, and it genuinely cannot reach the conversation**: 0.2.0 retired the whole axis because "a weight can only be written as `body, body *`, which cannot avoid the conversation". This round measured that rule on a live DSH page and found the isolation point: **exclude the whole conversation markdown subtree (and the code surfaces) from the rule with `:not()`**. Measured against computed styles on a live DSH page: with the exclusion, `body, body *` takes every interface text element to the chosen weight and **moves not one element inside the markdown subtree**; without it, the same configuration drags the conversation along. The interface weight is now an independent axis in the **Interface** section (it appears when following is off), 300–600, and its readout shows 400 like the others. The code side gets its fallback back too: once an interface weight is set, code surfaces without a weight of their own are explicitly reset to `normal` (which is what DSH computes there), so code blocks are not dragged along either.
- **Every "follows the interface" note in the conversation section is gone**: the follow direction has been one-way (the interface follows the conversation) for a while, but four small hints still claimed "unset follows the interface offset / weight / ratio" and "empty follows the interface font". All four now describe what actually happens ("0 keeps DSH's sizes", "unset keeps DSH's own weights", "100% keeps DSH's own line heights"), and a regression test now refuses the strings "跟随界面" / "follows the interface" in those four entries in both dictionaries. The interface section's follow row gained a "Font and weight" hint line naming what the switch covers.
- **The follow switch now covers the font and the weight**: on (the default), the interface takes the conversation's **font and weight** and its own two controls stay hidden; off, the interface uses its own font and weight and neither side can disturb the other. While following, a conversation that sets no weight still falls back to the interface's own stored value (the same fallback the family uses), so upgrading loses nothing.
- **The card's previews no longer lie**: the interface weight is an `!important` page-wide rule, so it used to restyle the card's own preview boxes as well. The conversation preview now carries a `dfp-previewDialog` marker, is excluded from the interface rule and receives the conversation weight on its own; the code preview stays on the code axis (it is already in `CODE_SELECTOR`) and the interface preview stays inside the interface rule — all three previews now match the surface they simulate.

## [0.2.0] - 2026-09-16

### Added
- **Three typography sets**: typography grows from two sets (body / code) to **three** — the **conversation** (markdown paragraphs, tables, headings) owns **every axis** (font, size, line height, weight); the **interface** (settings sheet, sidebars, workspace, headings and buttons) offers **a font only** and **follows the conversation by default** (switchable); **code** stays its own axis. The conversation is scoped through the markdown container (`[class*="_markdown_" i]` plus `:not()` complex selectors that exclude code surfaces) instead of hashed class names.
- **A conversation size axis**: -3 to +6 px, added **on top of the official "conversation font size"** (`--dsh-content-font-size`), which stays the base. The offset is added once, at the **source**: `--dsh-content-font-size` becomes "official value + offset", and the secondary size, both deltas and every delta-derived heading size and line height follow by derivation — paragraphs, headings and heights move together, with nothing counted twice. The official slider keeps working (its changes arrive through `theme/change`).
- **A conversation line-height axis**: a ratio of 100%–160% (step 5) that rebuilds the inline heights inside the markdown `font` shorthands; the **code line height** is its own additive offset (-4 to +8 px), composing with the code size offset.
- **Code ligatures**: a three-mode switch (default / on / off) writing `font-variant-ligatures` — browsers enable them by default, so this is the switch for turning them off — plus a sanitized advanced `font-feature-settings` value field (`"ss01" on, "cv01" 1` shape).
- **Refuse synthetic styles**: stops synthetic italic and synthetic bold for faces without them (`font-synthesis-style` / `font-synthesis-weight`); simple mode is one switch for both, advanced mode two independent switches.
- **The interface follows the conversation (switch)**: the conversation is the full set while the interface has a font, so **the interface follows the conversation by default** — the conversation section has no switch and all four of its axes stay adjustable, and the interface section leads with a "Follows the conversation" switch (on by default) whose font control appears only once it is switched off (the interface's own value stays as the fallback meanwhile). Because an unset conversation font falls back to the interface's, **existing configurations look exactly as before**.
- **Presets**: a **dropdown select** right under the edit mode (the card's own down chevron inside the box), with five built-in presets (默认配置 1 ~ 5) out of the box — picking one applies it, and **every change afterwards auto-saves into the selected preset** (no separate save step). "Rename / Export / Import" manage the list: renaming only changes the name and keeps the stored values, exporting copies JSON and importing merges by name (imports run the same sanitizer pipeline, capped at 20). Presets and the active preset name live in the host settings document, so they travel across browsers. Operation results ("copied to the clipboard") appear on the right of the row below and **fade out by themselves after about 2.6 s**, without moving any layout.
- **Card information architecture**: top to bottom the open card becomes an edit-mode row, a **preset bar** and three **accordion sections** — **conversation → interface → code** (the conversation leads because it owns every axis) — all collapsed by default, each title row carrying a summary with the chevron pinned to the far right, at most one open at a time; "refuse synthetic styles" is one or two switches, so it **no longer earns an accordion** and sits flat below the three sections. Expanding a section ends with that section's own **inline preview box** (rendering just that part; a floating variant was tried first and reverted after real-machine feedback). **Row format lines up with dsh-quick-toc**: every setting is a field row with 14px vertical padding (was 16px), every on/off control is the joined "one box split in two" segmented control (28px tall, was a 22px pill switch), and the control sits in the same row as its label, right-aligned (`.dfp-inline`, the same shape as quick-toc's `.dqt-pinline`) — so the two cards' rows and controls align.
- **The interface size / line-height / weight axes are RETIRED (measured)**: DSH exposes **no interface size hook** — the settings sheet, both sidebars and the workspace size their text with literals in upstream CSS (22 literals in settings-plugins, 18 in workspace, 6 in sidebar, **0** uses of the interface ladder tokens), and the ladder tokens (`--dsw-font-xs-13`, `--dsw-font-s-14`, …) are consumed only by 6 conversation-area packages (tool / trajectory / attachment / chat / conversation / cordis). The only official size hook is the conversation one. Scaling the ladder from these fields could not reach the settings sheet or the sidebars, while it reached the **conversation** through `--dsh-content-font-size` — the root cause of "I change the interface and the conversation moves". Weight is worse: it can only be expressed as a `body, body *` rule, which cannot avoid reaching the conversation either (narrowing it off the markdown subtree would also strip the theme's own heading weights). So **size, line height and weight belong to the conversation alone**, and the interface keeps the one axis that measurably works: its font (a page-wide `body` rule plus the theme variable). The `sizeOffset` / `lineHeight` / `weight` fields stay in the schema (old documents and presets keep parsing) but inject nothing at all.
- **Per-theme values ship out of this release**: light and dark share one value set — the top-bar per-theme switch and the light/dark editor are removed (the dark fields stay in the host schema but dormant, and rendering ignores them), to be re-evaluated in a later release.

### Fixed (real-machine walkthrough)
- **Preset messages no longer linger, and no longer move the layout**: a note like "Presets copied to the clipboard." used to sit in the card forever and, as a fresh line, push the sections below it down. It now **shares one row** with "With a preset selected, every change saves into it automatically": the message fades in on the **right** of that row and **fades out by itself after 2.6 s** (a 0.24 s opacity transition, then the text is cleared). The row is **always mounted** and exactly one line tall, and the message is clamped with `nowrap + ellipsis` — so appearing and disappearing never changes the row height and nothing below ever moves. Two identical actions in a row still work (each message carries an incrementing id, and the auto-hide timer restarts), and an over-long message (the clipboard-unavailable fallback, say) stays readable on hover through its `title`.
- **"I change the interface and the conversation moves"**: the interface size axis scaled the conversation's official content-size chain (`--dsh-content-font-size` / the secondary size) alongside the interface ladder, and every markdown size derives from that chain — so an interface edit really was a conversation edit. The interface axis is now explicitly barred from it (`bodyTokenNames` excludes `--dsh-content-font-*`), and the interface size axis itself is retired for the reason above.
- **The conversation size offset used to move headings but not paragraphs**: the old implementation only rewrote the delta tokens and literal sizes, while paragraphs take their size from `var(--dsh-content-font-size,14px)` — and `var()` inside a custom property resolves where the property is **declared**, so a deeper scoped override cannot reach it. The new implementation declares `--dsh-content-font-size` as "official value + offset" at the source, so paragraphs, headings and line heights all follow.
- **Dark overrides used to be shadowed by the light values**: the per-theme resolver merged the dark map over an **already-expanded** value set, so as soon as the follow rule changed direction the borrowed values could overwrite the dark ones. The dark overrides are now merged over the raw values and expanded afterwards, so a dark font can no longer be clobbered by a light value.
- **Weight readouts read 400**: an unset weight used to print "unset" while the slider sat at 400 and the hint said 400 keeps DSH's own — three statements that disagreed. An unset weight now reads **400** (conversation and code weights both).
- **The % vanished while dragging the line-height slider**: the pending readout had no unit and only gained one on release — the pending readout now keeps the `%` too (the size / code-height `px` prefixes already did).
- **The conversation section showed English "variable names"**: the dialog axis label keys (`dialog.*`, `size/line/weight.dialogLabel`…) were missing from the bilingual dictionaries, so `translate` fell back to the key names — both dictionaries are complete now.
- **The first control sat too far from the section title**: field rows carry 16px top padding on top of the section body — the first field of a section body is tightened to 10px.
- **The chevron left the far right edge when expanded**: with the summary gone nothing pushed it there — an expanded section renders a flexible spacer instead, so the arrow stays pinned in both states.

### Changed
- **Family variables ride the official theme layer**: `ctx.theme.overrideTokens` registers `--dsw-font-family` and `--ds-font-family-code`/`--dsw-font-mono` as `{light, dark}` pairs, so the presenter owns them on body's inline style after every theme switch — the families no longer depend on stylesheet timing against the token rewrite. The `theme/change` event re-reads the tokens and repaints immediately (the official font-size preference flows through it), with the 4-second poll kept as a fallback.
- **Compatibility table** lists 0.2.0 as the latest version; the README is restructured around the three typography sets and presets, and `docs/` now holds the 0.2.0 research and specification records (not shipped in the package).

## [0.1.0] - 2026-09-14

First release. The architecture is a dual-half plugin (host + client): the client half owns the settings card and the style injection, the host half registers the settings namespace and ships the saved declarations with the served index.

### Added
- **Plugin settings card**: a host settings namespace registered under `settings.plugin.item` with the key `dsh-fonttune`, so it appears in **Settings → Plugins → Plugin configuration**; saving and resetting go through DSH's own settings document (`settings.yaml`).
- **Body / code font families**: two independent CSS font-family fallback lists, each allowed to be empty (= leave DSH's own stack alone).
- **Font picker panel**: four preset groups (monospace / CJK / Latin / generic); on Chromium `queryLocalFonts()` adds an "installed on this machine" group; a name that is not in the list can be created with "use xxx"; every row renders in its own font.
- **West / CJK split (simple mode)**: a switch at the top of the card — **simple mode** splits the stack into a Western and a CJK single-pick slot (one pair for body, one for code) while keeping one stack underneath; **advanced mode** is the full chip editor. The semantics are "simple mode only touches the front": the Western slot is the first non-CJK entry (picking replaces it in place, or prepends when there is none) and the CJK slot is the first CJK entry (picking replaces it in place, or **inserts right after the Western slot** when there is none, which keeps `Western, CJK, generic` CSS semantics correct). Everything beyond the two slots keeps its order and is shown as an "other fallbacks" note. **Switching modes is a pure view switch that writes nothing.** CJK classification is name-heuristic first (a broad regex plus localized names containing CJK characters); canvas measurement only confirms names that do not look CJK, so a preset family that is not installed still lands in the CJK slot. The switch row is a label on the left and a segmented toggle on the right.
- **Drag to reorder**: the selected families are a chip list with drag reordering, plus earlier/later buttons for keyboard and touch.
- **Live preview**: mixed Chinese/English plus a code line, rendered from the current configuration.
- **Global font-size offset** (-3 ~ +6 px): rescales DSH's own size tokens (`--dsh-content-font-size`, `--dsw-font-*-font-size` / `-line-height`) with the base read live, so it **stacks** with DSH's own font-size setting instead of overriding it; the token list is discovered at runtime with a built-in fallback map.
- **Global font weight** (300 ~ 600, any integer): applied through `body, body *`; 400 and "unset" both mean "leave DSH's own weight alone".
- **Commit-on-release sliders**: dragging the size-offset or weight slider only updates a local value and its readout — the write happens once on `pointerup` / `touchend` (window capture-level listeners) or on blur/keyup, so dragging never recomputes the size tokens and rewrites the settings document per step. **The local value also stays on screen until the host confirms it**: clearing it immediately would show the old committed number for one frame ("bounces back, then settles"); a repeated `pointerup` is guarded by an "already awaiting confirmation" flag so the same value is never written twice.
- **No first-paint font flash**: the host half listens on `webserver/index-inject` and injects the same declarations, so the first paint is already correct.
- **Bilingual copy** (Chinese/English) with a Chinese fallback; `queryLocalFonts` unavailability or refusal falls back to the built-in list silently.
- **Family-name sanitizing**: names are filtered through an allowlist and then quoted as a whole (letters/digits/space/`.` `,` `_` `-` only); the host schema adds a `^[^{};<>\\]*$` pattern and a length cap. A hand-crafted CSS injection cannot close a declaration or start a rule.

### Fixed
- **The card crashed on first render** (a release blocker): `scope.subscribe` was passed to React's `useSyncExternalStore` as a bare method reference, while the host's `SettingsScopeController.subscribe` is a prototype method reading `this.store` — called detached, `this` is undefined → the slot entry crashed silently and the card never appeared in the plugin configuration page. Fixed by wrapping the subscribe in a closure that preserves `this`. The offline tests had missed it (the double's subscribe did not depend on `this` and the React double never called subscribe); both doubles now reproduce the bug.
- **Three size-offset defects**: ① missing `!important` — the theme writes `--dsh-content-font-size` **inline on body**, and an inline declaration beats a normal stylesheet rule, so the body itself was not scaled while descendants were, splitting the page's font size in two; ② a **self-pollution compounding loop** — the 4-second token refresh re-read the plugin's own stylesheet declarations as its base and multiplied the ratio again on every cycle ("the fonts keep growing"); fixed by skipping the plugin's own tags, reading `--dsh-content-font-*` from the body inline style, and no longer using computed styles as a base source; ③ **double scaling through the `var()` chain** — DSH's derived tokens (delta/secondary/markdown) all derive from `var(--dsh-content-font-size)`, so scaling them too multiplied the ratio twice; fixed by skipping tokens whose base contains `var(` and letting the variable chain carry them.
- **Families did not reach the conversation or sidebar**: markdown and sidebar CSS declare `font-family: var(--dsw-font-family)` themselves, truncating inheritance, so a body-level `font-family` never got through.
