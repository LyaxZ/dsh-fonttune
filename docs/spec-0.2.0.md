# dsh-fonttune 0.2.0 功能规格

> 2026-09-15 定稿。范围决策 + 卡片信息架构 + 各功能行为规格。背景调研见 [research-0.2.0.md](research-0.2.0.md)。
> 本文件不在 npm `files` 清单内，不随包发布。
>
> **⚠️ 这是设计阶段的记录，不是最终实现的说明书。** 真机走查后有四处以本文件为准会读错，**以 [README](../README.md) / [CHANGELOG](../CHANGELOG.md) 为准**：
> 1. **D3 分主题数值整条移出本版**（深浅色共用一套值）；宿主 schema 里的深色字段保留但休眠、渲染层强制忽略。
> 2. **界面的字号 / 行高 / 字重三个轴全部退役**（DSH 没有界面尺寸接口，字重只能靠 `body, body *` 表达、必然波及对话）——界面**只保留字体**，并**默认跟随对话**（开关在界面分区）。实测证据见 CHANGELOG 的 0.2.0 条目。
> 3. **跟随方向反过来**：不是「对话跟随界面」，而是「**界面跟随对话**」；卡片分区顺序也相应改为 **对话 → 界面 → 代码**。
> 4. **预设交互**改为「编辑模式正下方的下拉选择框 + 选中即自动保存」，预览由「常驻」改为「各分区展开后在分区末尾内联」。

## 一、版本范围（已定）

**共同前置**
- **D1** 写入迁移到 `ctx.theme.overrideTokens(source, {token: {light, dark}})`，修复"切主题丢字体"
- **D2** 与官方字号行（`ui-theme.fontSize` 12–17）正交复核，保证叠加语义干净

**主体功能**
- **A1** 行高独立轴：界面 / 对话（倍率）、代码（±px）
- **A3** 连字开关（代码作用域）+ 高级特性集
- **A5** 伪斜体/伪粗体合成开关（中文排版）
- **B1** 界面 与 对话 字体分离（旧"正文"轴拆成两套）
- **D3** 按主题分设：浅色/深色各存一套值
- **D4** 预设方案：存 / 切 / 删 / 导出 / 导入，存设置文档

**Backlog（留给 ≥0.3.0，届时再让用户选）**
- A2 字间距 / A4 可变字体轴 / A6 渲染微调（smoothing、text-rendering）
- B2 标题独立 / B3 行内代码 vs 代码块 / B4 bash 输出块独立
- C1 URL 字体导入 / C2 本地字体文件托管 / C3 测量式字体探测 / C4 常用字体名字预设
- D5 快速调整浮条 / D6 字体检查器 / D7 逐版本冒烟验证机制
- E 组不做：配色主题化、界面全局百分比缩放、抢占 General 席位

## 二、卡片信息架构（手风琴 + 顶栏 + 常驻预览）

设计原则：**首屏 = 摘要，不摊开**。每个分区默认收起，标题行右侧显示"当前值摘要"，点标题才展开该区；展开区自动收起其它区（同一时刻最多一个展开，预览常驻除外）。

```
┌ 字体增强 ────────────────────────────────────────┐
│ 正文与代码字体、字号、字重、行高与连字                  │
│                                                  │
│ 编辑模式  [简单|高级]     分主题设置 [开关]          │
│ 编辑主题  [浅色|深色]        ← 仅分主题开启时出现    │
│ ────────────────────────────────────────────────│
│ ▸ 界面      雅黑+系统 · 字号 +0 · 字重 400 · 行高 1.0│
│ ▸ 对话      跟随界面                               │
│ ▸ 代码      Cascadia · 字号 +0 · 400 · 行高 0 · 连字 │
│ ▸ 全局与微调  中文伪斜体：禁用                       │
│ ▸ 预设方案    3 个方案                              │
│ ────────────────────────────────────────────────│
│ 实时预览（中英混排 + 代码两行，常驻）                 │
│ [全部重置]                                        │
└─────────────────────────────────────────────────┘
```

### 2.1 顶栏（常驻，不折叠）

| 控件 | 行为 |
| --- | --- |
| 编辑模式 简单/高级 | 沿用现有语义：简单 = 每区只显示「西文」「中文」两个单选格；高级 = chips 编辑器 + 其余回退项提示 + 连字特性集等高级项。纯视图切换，零写入 |
| 分主题设置 开关 | 关 = 全部轴单套值（现状形态）；开 = 顶栏出现「编辑主题 浅色\|深色」，下面所有分区编辑的都是当前选中的那套；两套各自完整存储。开关本身持久化；关闭时保留已存的另一套值（重新打开即回来） |
| 编辑主题 浅色\|深色 | 分段控件，切换"正在编辑哪一套"；值变化即时预览当前主题的效果（若当前页面主题 ≠ 正在编辑的主题，预览区显示被编辑主题的效果并在旁边小字提示） |

### 2.2 分区一「界面」（侧栏 / 设置页 / 按钮等界面文字）

| 控件 | 形态 | 范围 / 默认 |
| --- | --- | --- |
| 字体 | 简单：西文格 + 中文格；高级：chips 栈编辑器（沿用现有交互） | 空 = 沿用 DSH |
| 字号偏移 | 滑块，-3 ~ +6 px，step 0.5，0 = 不动 | 与官方字号行叠加 |
| 字重 | 滑块，300–600，step 1，0/未设 = 不动 | |
| 行高 | 滑块，1.0× ~ 1.6×，step 0.05，1.0 = 不动 | 等比缩放界面行的行高 |

### 2.3 分区二「对话」（AI 回复正文区）

控件同「界面」四轴。差异：

- **未设置任何值时显示「跟随界面」**（摘要行同文案）——这是 0.1.x 用户升级后的默认：旧配置里 `sans`/`sizeOffset`/`weight` 归「界面」，「对话」留空 = 完全跟随界面，**老用户升级后视觉零变化**。
- 对话区的实现走 `--dsw-font-markdown-base` 族 token（含 h1..h4/table 的派生），界面走 `--dsw-font-family`——token 级覆盖，不碰哈希类名。
- 对话字号与官方字号行（General 的 12–17 步进器）正交：官方调档驱动 `--dsh-content-font-delta`，本插件的偏移是**其上的增量**，两边可任意组合（D2 的验收标准）。

### 2.4 分区三「代码」（代码块 / 行内代码 / bash 输出块）

| 控件 | 形态 | 范围 / 默认 |
| --- | --- | --- |
| 字体 | 同上（mono 栈） | 空 = 沿用 DSH |
| 字号偏移 | 滑块，-3 ~ +6 px | |
| 字重 | 滑块，300–600 | |
| 行高 | 滑块，-4 ~ +8 px，0 = 不动（代码用像素不倍率，与 0.1.4 的简写重写机制同构） | 连同简写 token 的行高分件一起重写 |
| 连字 | 开关（关 = 不动；开 = 启用连字） | 选择器复用 0.1.5 字重代码规则的那套作用域（pre/code/…/`[class*="code" i]`/terminal） |
| 连字特性集（高级） | 文本输入：逗号分隔的 OpenType 特性标签（如 `ss01, cv01`），空 = 只开基础连字 | 写入 `font-feature-settings`；仅高级模式显示 |

### 2.5 分区四「全局与微调」

| 控件 | 形态 | 行为 |
| --- | --- | --- |
| 中文伪斜体 | 开关（三态：跟随默认 / 禁用）→ 高级模式拆成「伪斜体」「伪粗体」两个独立开关 | `font-synthesis-style: none` / `font-synthesis-weight: none`，作用于全页文本；摘要行显示当前状态 |
| （随版本追加的微调项归此区） | | 保持"最多两三个控件"的规模，防止本区变杂物抽屉 |

### 2.6 分区五「预设方案」

存储在设置文档（跨浏览器、可导出）。字段形态为实现细节（倾向 `presets` 对象/JSON 串，含名字 + 完整轴值快照 + 保存时间）。

| 操作 | 行为 |
| --- | --- |
| 保存当前 | 输入名字 → 把当前生效的全部轴值存为一个方案；重名时提示覆盖 |
| 方案列表 | 每行：名字 + 一行摘要（如「宋体 · 行高 1.4 · 连字」）+ 应用 / 覆盖 / 删除 |
| 应用 | 整套替换当前轴值（带一次确认？不用——设置页本身可重置）；应用后滑块与摘要全部刷新 |
| 导出 | 生成 JSON 文本（复制到剪贴板 / 下载文件） |
| 导入 | 粘贴 JSON 或选文件 → 校验（版本兼容 + 字段消毒，走现有 sanitize 管线）→ 列表里新增，不自动应用 |

预设里**不含**分主题的另一半（只存当前编辑主题的值？）→ 决定：**方案存"单套值"**；应用方案时只覆盖当前正在编辑的主题那套，另一套不动。理由：方案的语义是"排版风格"，主题分设是正交维度。

### 2.7 实时预览（常驻）

现有中英混排 + 代码两行，追加行高的直观呈现（行距拉开）；连字开启时代码行直接演示 `=> != >=` 等样例。分主题开启时预览跟随「编辑主题」的值。

### 2.8 复杂度控制红线（本版硬约束）

- 任何时刻卡片可见控件 ≤ 顶栏 4 + 当前展开分区（≤6）+ 预览 + 重置；**收起状态下整卡一屏内看完**。
- 每个分区摘要必须能"不看内容就知道现状"（跟随/自定义 + 关键值），让用户大部分时候不用展开。
- 「全部重置」收编所有分区的重置语义（现有已修改/单独重置的逐字段机制保留在展开区内）。

## 三、数据与迁移

### 3.1 设置字段（0.2.0 目标形态）

```
stackUi          （旧 sans 迁移）
stackDialog      （空 = 跟随 stackUi）
stackCode        （旧 mono 迁移）
sizeOffsetUi / weightUi / lineHeightUi     （旧 sizeOffset/weight 迁移到 Ui）
sizeOffsetDialog / weightDialog / lineHeightDialog
sizeOffsetCode / weightCode / lineHeightCode / codeLigatures / codeFeatures
noSyntheticItalic / noSyntheticBold
perTheme         （bool，分主题开关）
light / dark     （各一整套上述值的快照；perTheme 关时只有 light 层生效语义）
presets          （JSON 串：[{name, values, savedAt}]）
```

旧配置升级：读入时把 `sans→stackUi`、`mono→stackCode`、`sizeOffset→sizeOffsetUi`、`weight→weightUi` 平移，`stackDialog`/行高/连字全空，`perTheme=false`——**行为与 0.1.6 完全一致**。

### 3.2 注入双路径（D1 迁移后）

- **宿主半 index-inject**（保留）：首绘前的预涂装，读设置文档生成同样的声明——hydration 前首帧就有字体；另评估 BeiZi6 验证过的 `webServer.tapIndex` 官方接缝作为替代/补充。
- **客户端半 `ctx.theme.overrideTokens`**：运行时的权威写入路径，token → `{light, dark}` 对；`theme/change` 后由官方 presenter 重放，切主题不再丢。
- **非 token 的 CSS**（字重全量规则、行高代码简写重写、连字、font-synthesis）：仍走注入 `<style>`；分主题开启时用 `body[data-ds-dark-theme]` 前缀区分两套值（shiki.css 同款写法）。

### 3.3 兼容性

`engines.dsh` 仍 `>=0.1.5-rc.2`；兼容表只列 0.1.5 线最新。版本号 bump 到 **0.2.0**，README/CHANGELOG 双语、卡片描述、npm description 同步改；市场文案更新走 awesome-dsh-plugin PR（惯例：先问用户要不要动市场条目）。

## 四、验收清单（离线测试需覆盖的新场景）

1. 旧配置升级等价性（0.1.6 值 → 0.2.0 字段 → 生成 CSS 与旧版逐字节一致）
2. overrideTokens 迁移后：模拟 theme/change 不丢声明；`{light,dark}` 成对、裸字符串拒绝路径
3. 对话未设置 = 跟随界面（CSS 不生成对话覆盖规则）
4. 对话与官方字号叠加：官方 delta 变化时对话仍按"官方档 + 增量"渲染（与 D2 验收一致）
5. 行高三轴：倍率边界（1.0/1.6）、代码 ±px 与简写 token 行高分件同步重写
6. 连字：作用域选择器命中全部代码表面；特性集消毒（白名单字符、闭合防御）
7. 分主题开关三态往返（关→开→关）后值不丢、CSS 恢复单套
8. 预设：保存/应用/删除/导入导出往返；导入含非法字段的拒绝路径
9. 手风琴摘要行与实际轴值的一致性（改值即刷新摘要）
10. 双语文案键一致性（新分区/新控件全键位）

## 五、实施顺序（建议）

1. shared.cjs 数据模型与迁移（字段重命名 + 旧配置平移 + buildFontCss 三分区重构）
2. D1 overrideTokens 客户端接入 + 宿主预涂装双路径打通（含主题切换回归）
3. A1 行高轴（基建最近，先出活）
4. A3 连字 + A5 伪斜体（小体量 CSS 特性）
5. B1 界面/对话分离（依赖 1 的字段形态）
6. D3 分主题（全局开关 + light/dark 双套 + CSS 侧 data-ds-dark-theme）
7. D4 预设方案（依赖 1–6 全部轴定稿）
8. 卡片手风琴重构（2.2–2.7 的 UI 形态 + 摘要行）——建议与 3–7 并行推进、最后收口
9. 离线测试扩充 + README/CHANGELOG 双语 + 发布流程（照 quick-toc 惯例：commit → push → tag → npm publish → 三方哈希核对）
